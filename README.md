# ConverterReport 2.0

Сборка суточного отчета о ходе устранения замечаний ГГЭ **в один PDF** по данным файлов «Экран» этапов.

Программа сама делает то, что раньше делалось вручную в книге отчета:

| Было (вручную) | Стало (автоматически) |
| --- | --- |
| Создать лист «ДД.ММ» копированием предыдущего, поправить дату и время отчета | Дата и время берутся автоматически — ближайшее стандартное время (08:00 / 18:00) или из параметров запуска |
| Скопировать данные «Документы» из экранов, выводилась только **последняя** загрузка | **Суммируются все загрузки** за отчетный период (с 18:00 предыдущего дня по время отчета) |
| Скопировать данные «Замечания» из экранов | Строка на отчетные дату/время берется из каждого экрана; изменения за период считаются сами |
| Обновить Power Query, поправить диапазоны диаграмм на листе «Свод» | Диаграммы строятся заново при каждом запуске по актуальным данным экранов |
| Сохранить в PDF лист отчета, детальный отчет и диаграммы, убрать пустые листы | Один PDF: **отчет на дату → детальный отчет → диаграммы**, пустые страницы не выводятся |
| Состав этапов «зашит» (5 шт.) | **Любое количество этапов** — перечисляются в файле настроек |

## Что входит в PDF

1. **Суточный отчет** (как лист «ДД.ММ»):
   1. Загрузка документов в АИС ГГЭ за период — по каждому этапу сумма всех загрузок
      (ИИ, ПД, сметы, ВОР, КАЦ, иные, всего), количество загрузок, начало первой и окончание последней.
      Этапы без загрузок скрываются. Режим `"LoadsMode": "Each"` выводит каждую загрузку отдельной строкой с итогом по этапу.
   2. Устранение замечаний — все и критические (всего / устранено / устраняется / на рассмотрении, шт. и %).
   3. Изменение за период и итоговая фраза «На текущую дату не устранено …».
   4. Сроки (входной контроль, экспертиза, продления) — текущая стадия подсвечивается.
   5. «Справочно» — текст из файла `Справочно.txt` (если файл пуст, раздела нет).
2. **Детальный отчет** (как лист «Отчет_дет»): все замечания и «в т.ч.» инженерные изыскания, тех. часть, сметная часть.
3. **Диаграммы** — сводная по всем этапам и по каждому этапу:
   «Устранение замечаний ГГЭ» (устраняется / рассматривается / устранено за сутки, линии «Всего» и «Устранено»,
   линия тренда, отметка окончания экспертизы) и «Загрузка документов в АИС ГГЭ» по дням.

Проверки, как в книге: если «Всего» не равно сумме по статусам или сумме по разделам — ячейка подсвечивается
красным и выводится предупреждение. Если в экране не заполнена строка на отчетное время, используется последняя
заполненная, у номера этапа ставится «*» и в отчете есть сноска.

Дополнительно (по настройке или параметру запуска):
* отдельный PDF по каждому этапу (`--per-project`), имя: `ГГГГ.ММ.ДД ЧЧ.ММ Суточный отчет ГГЭ N этап.pdf`;
* выгрузка рассчитанных данных в Excel (`--excel`) — сводка, загрузки за период, динамика по дням (для сверки).

## Быстрый старт

1. Собрать программу (нужен .NET 8 SDK) — `publish.cmd` или:
   ```
   dotnet publish src/ConverterReport -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -o publish
   ```
   Получится `publish\ConverterReport.exe`, которому не нужен установленный .NET.
   Готовую сборку также можно скачать из раздела **Actions** репозитория (артефакт `ConverterReport-win-x64`).
2. Создать файл настроек рядом с программой: `ConverterReport.exe --init` (или скопировать `ConverterReport.sample.json`
   в `ConverterReport.json`) и указать в нем пути к файлам экранов и сроки этапов.
3. Запустить `ConverterReport.exe` (двойным щелчком или из командной строки). PDF появится в папке `Отчеты`.

> Файл `ConverterReport.json` с реальными путями и `Справочно.txt` в репозиторий не коммитятся (см. `.gitignore`) —
> репозиторий публичный.

## Параметры запуска

```
ConverterReport [параметры]
  -c, --config <файл>      файл настроек (по умолчанию ConverterReport.json в текущей папке или рядом с программой)
  -d, --date <дд.мм.гггг>  дата отчета (по умолчанию сегодня)
  -t, --time <чч:мм>       время отчета (по умолчанию ближайшее из ReportTimes: в 07:50 → 08:00, в 17:40 → 18:00)
      --from "<дд.мм.гггг чч:мм>"  начало отчетного периода (по умолчанию 18:00 предыдущего дня)
  -o, --out <папка>        папка для PDF
      --per-project        дополнительно PDF по каждому этапу
      --excel              дополнительно выгрузка рассчитанных данных в Excel
  -n, --note "<текст>"     добавить строку в раздел «Справочно» (можно несколько раз)
      --open               открыть PDF после формирования
      --init               создать пример файла настроек
      --no-pause           не ждать нажатия клавиши (для планировщика задач Windows)
```

Примеры:
```
ConverterReport.exe
ConverterReport.exe -t 18:00 --open
ConverterReport.exe -d 15.10.2026 -t 08:00 --per-project
```

Для автоматического формирования по расписанию добавьте задачу в Планировщик заданий Windows с аргументами
`-t 08:00 --no-pause` (и вторую — `-t 18:00 --no-pause`). Журнал работы пишется в `Отчеты\ConverterReport.log`.

## Файл настроек `ConverterReport.json`

Минимально нужно перечислить этапы — их может быть сколько угодно:

```json
{
  "Projects": [
    { "Number": "2", "ScreenFile": "\\\\server\\share\\2 этап\\Экран ГГЭ 2 этап.xlsx" },
    { "Number": "3", "ScreenFile": "\\\\server\\share\\3 этап\\Экран ГГЭ 3 этап.xlsx",
      "Deadlines": {
        "Входной контроль": [ "11.06.2026", "24.06.2026" ],
        "Экспертиза":       [ "25.06.2026", "24.08.2026" ],
        "Продление 1":      [ "25.08.2026", "21.09.2026" ],
        "Продление 2":      [ "24.09.2026", "18.11.2026" ]
      }
    },
    { "Number": "9", "ScreenFile": "Экраны\\Экран ГГЭ 9 этап.xlsx", "Enabled": false }
  ]
}
```

Все остальные настройки необязательны (значения по умолчанию — в `ConverterReport.sample.json`).

### Этапы (`Projects`)

| Параметр | Назначение |
| --- | --- |
| `Number` | номер этапа, как он выводится в столбце «Этап» (подзаголовок «по 2-4, 9 этапам» собирается из номеров автоматически) |
| `ScreenFile` | путь к файлу «Экран» (абсолютный, сетевой или относительно файла настроек). Файл читается, даже если он открыт в Excel |
| `Enabled` | `false` — временно исключить этап, не удаляя его из настроек |
| `Name` | имя для заголовков диаграмм и файла (по умолчанию «N этап») |
| `Deadlines` | сроки для раздела «4. Сроки»: стадия → `[начало, окончание]` или `["произвольный текст"]` |
| `ExpertiseEndDate` | дата окончания экспертизы (по умолчанию — наибольшая дата из `Deadlines`) — для отметки на диаграмме и «Осталось дней» |
| `ChartStartDate` | с какой даты строить диаграммы (по умолчанию — с начала сроков, т.е. входного контроля) |

### Отчет (`Report`)

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `ReportTimes` | `["08:00","18:00"]` | стандартные времена отчета (для автоматического выбора) |
| `PeriodStartTime`, `PeriodStartDayOffset` | `"18:00"`, `-1` | начало отчетного периода — 18:00 предыдущего дня |
| `OutputFolder` | `"Отчеты"` | папка для PDF |
| `FileName` | `"{date:yyyy.MM.dd} {time:HH.mm} Суточный отчет ГГЭ"` | имя общего PDF |
| `ProjectFileName` | `"… Суточный отчет ГГЭ {number} этап"` | имя PDF по этапу |
| `PerProjectReports`, `ExportExcel` | `false` | то же, что `--per-project` и `--excel` |
| `IncludeDaily`, `IncludeDetailed`, `IncludeCharts`, `IncludeDeadlines` | `true` | какие части включать в PDF |
| `LoadsMode` | `"Sum"` | `Sum` — сумма загрузок за период по этапу, `Each` — каждая загрузка отдельной строкой |
| `HideProjectsWithoutLoads` | `true` | скрывать в разделе 1 этапы без загрузок за период |
| `NotesFile` | `"Справочно.txt"` | файл с текстом раздела «Справочно» |
| `Title`, `Subtitle`, `ProjectsCaption`, `DetailedTitle` | | заголовки |

### Диаграммы (`Charts`)

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `PageSize` | `"A4"` | `A4` или `A3` (альбомная). На A3 помещаются подписи значений над столбцами |
| `SummaryChart` | `true` | сводная диаграмма по всем этапам |
| `StartDate` | — | общая дата начала диаграмм |
| `ExtendToExpertiseEnd` | `true` | продлевать ось дат до окончания экспертизы |
| `TrendLine` | `true` | линия тренда (прогноз) по устраненным |
| `DataLabels` | `"Auto"` | подписи значений: `Auto` / `All` / `Last` (только на отчетную дату) / `None` |

### Раскладка экрана (`ScreenLayout`)

Значения по умолчанию соответствуют текущему шаблону «Экрана»:

* лист **«Замечания»**, данные с 3-й строки: B — дата, D — время, E–H — замечаний всего / устранено / устраняется /
  рассматривается, I–L — инженерные изыскания, M–P — тех. часть, Q–T — сметная часть, U–X — критических,
  Y–AB, AC–AF, AG–AJ — критические по разделам. Строка учитывается, если заполнен столбец E;
* лист **«Документы»**, данные с 3-й строки: H/I — начало загрузки (дата/время), J/K — окончание, L–Q — ИИ, ПД, СМ,
  ВОР, КАЦ, иные (столбец «Всего» считается как их сумма), S — ответы, T — аннулировано, U — ошибки.
  Дата и время могут быть датой Excel, датой со временем или текстом («10.10.2026», «18:56»).

Если шаблон экрана изменится (добавятся столбцы), достаточно поправить буквы столбцов в этом разделе.

## Как считается

* **Время отчета** — ближайшее к моменту запуска из `ReportTimes` (или `--date`/`--time`).
* **Отчетный период** — с 18:00 предыдущего дня до времени отчета (как в книге: `AE3 = AE4 - 1`, `AF3 = 18:00`).
* **Загрузки за период** — все строки «Документов», у которых окончание загрузки попадает в период
  (начало периода не включается, время отчета включается). По этапу суммируются все такие загрузки.
* **Состояние замечаний** — строка экрана на дату и время отчета (если ее нет — последняя заполненная раньше,
  с пометкой «*»). **Изменение** — разница со строкой на начало периода.
* **Диаграммы** — по каждому дню берется последняя заполненная строка дня (не позже времени отчета);
  «Устранено за сутки» — разница с предыдущим днем; загрузки — сумма по дате окончания.
  В сводной диаграмме этапы суммируются (если у этапа строка за день не заполнена, берется последнее значение).

## Структура решения

```
src/ConverterReport.Core     — библиотека: чтение экранов, расчет, PDF, выгрузка в Excel
  Configuration/             — настройки (JSON)
  Screens/ScreenReader.cs    — чтение «Экрана» (ClosedXML, только чтение, файл может быть открыт)
  Reporting/                 — расчет отчета и рядов диаграмм, выбор времени отчета
  Pdf/                       — MigraDoc-разметка отчета, векторные диаграммы, удаление пустых страниц
  Export/ExcelExporter.cs    — выгрузка в Excel
src/ConverterReport          — консольная программа
tests/ConverterReport.Tests  — тесты (xUnit) на синтетических данных
```

Используемые библиотеки — с открытыми лицензиями (MIT): ClosedXML, PDFsharp/MigraDoc. Excel для работы программы не нужен.
Шрифты: на Windows — Times New Roman и Arial; на Linux — Liberation/DejaVu; можно положить `.ttf` в папку `fonts`
рядом с программой.

Сборка и тесты:
```
dotnet build
dotnet test
```

попадали. Чтобы перенести их сюда, загрузите папку проекта в ветку (например, в каталог `legacy/`), после чего
