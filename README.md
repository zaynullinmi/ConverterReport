# ConverterReport 2.0

Суточный отчет о ходе устранения замечаний ГГЭ по данным файлов «Экран» этапов — **без ручной работы**.
За один запуск программа делает:

1. **Сводную книгу Excel** со структурой книги отчета — листы, формулы и ссылки, диаграммы;
2. **три PDF**, как при ручном сохранении:

| Файл | Что внутри | Формат |
| --- | --- | --- |
| `2026.10.15 8.00 Свод ГГЭ 2-4,9 этапы 1.0.pdf` | отчет на дату (лист «ДД.ММ»): загрузки, устранение замечаний, изменения за период, сроки, справочно | A4 |
| `2026.10.15 8.00 Свод ГГЭ 2-4,9 этапы 1.0 Отчет.pdf` | детальный отчет (лист «Отчет_дет»): все замечания и в т.ч. ИИ / тех. часть / сметная часть | A4 |
| `2026.10.15 8.00 Свод ГГЭ 2-4,9 этапы 1.0 Диаграммы.pdf` | диаграммы: сводная по всем этапам и по каждому этапу | A3 альбомная, каждая страница — по ширине листа |
| `2026.10.15 8.00 Сводный отчет ГГЭ 2-4,9 этапы ВСМ-1 1.0.xlsx` | сводная книга | — |

Имена файлов задаются шаблонами в настройках (см. ниже).

| Было (вручную) | Стало (автоматически) |
| --- | --- |
| Создать лист «ДД.ММ» копированием предыдущего, поправить дату и время отчета | Лист строится заново; дата и время — ближайшее стандартное (08:00 / 18:00) или из параметров запуска |
| В разделе 1 выводилась только **последняя** загрузка | **Суммируются все загрузки**: в вечернем отчете — за день (как на диаграмме), в утреннем — с 18:00 предыдущего дня по время отчета (настройка `ReportLoads`) |
| Скопировать «Документы» и «Замечания» из экранов, обновить запросы | Листы Д.N и З.N копируются из экранов при каждом запуске |
| Поправить диапазоны диаграмм на листе «Свод» | «Свод» и диапазоны диаграмм строятся по фактическому периоду |
| Сохранить в PDF три листа, убрать пустые страницы | Три PDF сохраняются сами; пустые страницы удаляются, этапы без данных не выводятся |
| Состав этапов «зашит» (5 шт.) | **Любое количество этапов** — список в файле настроек |

## Сводная книга

Структура — как у книги отчета:

| Лист | Содержимое |
| --- | --- |
| **Описание** | как сформирована книга |
| **Д.N**, **З.N** | копии листов «Документы» и «Замечания» экрана каждого этапа (даты и время приведены к датам Excel; в Д.N добавлены колонки W/X — начало и окончание загрузки «дата+время») |
| **Свод** | по дням: состояние замечаний (`СУММЕСЛИМН` по листам З.N на дату и время среза) и загрузки (`СУММЕСЛИМН` по листам Д.N по дате окончания); итог по всем этапам и блоки по 17 колонок на каждый этап — источник диаграмм |
| **Диаграммы** | на каждом листе A3: «Устранение замечаний ГГЭ» (устраняется / рассматривается / устранено за сутки, линии «Всего» и «Устранено» с линейными трендами) и «Загрузка документов в АИС ГГЭ»; строка «Всего: … Дата окончания экспертизы … Осталось дней» |
| **ДД.ММ** (например, «15.10») | суточный отчет. Справа от области печати — блоки «Конвертер», на которые ссылаются формулы отчета: **0/I** — начало периода и отчетные дата/время (`AE3:AF4`), **II** — загрузки за период (`СУММПРОИЗВ` по Д.N), **III** — замечания на отчетное время и **IV** — на начало периода (ссылки на строки З.N), **V** — изменение за период (III − IV) |
| **Отчет_дет** | детальный отчет, ссылки на лист «Отчет» |
| **Отчет** | данные по разделам (все / ИИ / тех. часть / сметная часть) — ссылки на строки З.N |

Все показатели в книге — формулы: если поправить данные на листах Д.N/З.N, отчет, свод и диаграммы пересчитаются.
«Всего» подсвечивается красным, если не равно сумме по статусам. Этапы без загрузок за период в разделе 1
скрываются (строки не удаляются). Если в экране не заполнена строка на отчетное время, берется последняя
заполненная, у номера этапа ставится «*» и выводится сноска.

## Общая книга (лист дня дописывается)

По умолчанию на каждый отчет создается отдельная книга. Если на вкладке «Отчет» выбрать
**«Дописывать лист дня в общую книгу»** (`"WorkbookMode": "Append"`), программа ведет одну книгу, как версия 1.2.2:

* лист отчета «ДД.ММ» добавляется в общую книгу; отчет за ту же дату (например, 18:00 после 08:00) заменяет лист;
* прежние листы дней сохраняются; видимыми остаются последние (по умолчанию 2, настройка
  «Общая книга: видимых листов дней»), остальные скрыты — показать: правой кнопкой по ярлыку → «Показать»;
* «Описание», Д.N/З.N, «Свод», «Диаграммы», «Отчет_дет» и «Отчет» обновляются на последний отчет;
  прежние листы дней ссылаются на Д.N/З.N и показывают те же числа, что и в день формирования;
* если книги нет — она создается; перед сохранением прежняя версия остается рядом как `….xlsx.bak`.

Программа дописывает только в книгу, которую создала сама (в свойствах книги есть отметка). Книгу прежнего
формата (которую вела версия 1.2.2) она не изменяет — для общей книги нужно указать новый файл. Если общая книга
открыта в Excel (у вас или у коллеги), лист в нее не дописывается: формируется отдельная книга и выводится
предупреждение — отчет и PDF получаются в любом случае.

**Листы прошлых дней из старой книги** (опция «Переносить листы прошлых дней из старой книги»,
`"ImportLegacyDays": true` и `"LegacyWorkbook"`): при каждом формировании в общую книгу добавляются листы «ДД.ММ»
старой книги за прошлые дни, которых в общей книге еще нет (листы, сформированные программой, не заменяются).
Листы переносятся как были — значениями (формулы старой книги ссылаются на соседние листы), с оформлением, скрытыми
строками и областью печати; цвета темы переводятся в явные, чтобы не изменились. Старая книга только читается
(даже если открыта в Excel). Сроки этапов, не заполненные в настройках, берутся из раздела «4. Сроки» последнего
листа старой книги и сохраняются в настройки. Первый перенос (около 200 листов) занимает 1–2 минуты; дальше,
когда переносить нечего, старая книга не открывается.

## Как сохраняются PDF

* **Через Excel** (по умолчанию, если Excel установлен): программа открывает сводную книгу в Excel,
  пересчитывает и сохраняет три листа в PDF — вид один в один как при ручном «Сохранить как PDF».
* **Встроенный генератор** — если Excel нет (или `"PdfEngine": "Builtin"`): PDF строятся без Excel,
  с той же структурой и оформлением.

## Быстрый старт

1. Скачать архив `ConverterReport-win-x64.zip` из раздела **Releases** репозитория (собирается автоматически
   при каждом обновлении `main`), распаковать в отдельную папку. Установленный .NET не нужен.
2. Запустить `ConverterReport.exe` — откроется окно программы. На вкладке **«Этапы»** указать файлы экранов
   и сроки этапов, на вкладке **«Отчет»** нажать **«Сформировать отчет»**. Книга и PDF появятся в папке `Отчеты`.

Если рядом с программой уже есть `ConverterReport.json` (настройки прежней версии), он подхватится сам.

> Файл `ConverterReport.json` с реальными путями, `Справочно.txt`, книги и PDF в репозиторий не коммитятся
> (см. `.gitignore`) — репозиторий публичный.

## Окно программы

| Вкладка | Что на ней |
| --- | --- |
| **Отчет** | дата и время отчета (по умолчанию ближайшее стандартное — 08:00 или 18:00; кнопка «Ближайшее»), начало периода вручную, папка для отчетов, какие PDF сформировать и чем их сохранять (Excel или встроенный генератор), сводная книга — новая на каждый отчет или общая (лист дня дописывается), текст «Справочно», кнопка «Сформировать отчет», ход работы и кнопки для открытия готовых PDF, книги и папки |
| **Этапы** | список этапов (любое количество): включен ли этап («Вкл.» — экран читается), выводится ли в отчет («В отчете» — если снять, этап будет только на сводной диаграмме), номер, название на диаграммах, файл экрана (кнопка «Обзор…»), окончание экспертизы, начало диаграмм, свой верх шкалы диаграммы загрузок; порядок этапов (кнопки «Выше»/«Ниже»), проверка, что все файлы экранов доступны; ниже — сроки выбранного этапа (стадия, начало, окончание) |
| **Настройки** | все остальные параметры с подсказками: заголовки, стандартные времена и начало периода, шаблоны имен файлов, раздел «Сроки», диаграммы, раскладка листов экрана, обновление программы |

Настройки сохраняются в `ConverterReport.json` рядом с программой (если в эту папку нельзя писать —
в `%APPDATA%\ConverterReport`) кнопкой «Сохранить настройки», `Ctrl+S` и перед каждым формированием отчета.
Меню «Файл» позволяет открыть или сохранить другой файл настроек.

## Обновление программы

При запуске программа проверяет последний релиз на GitHub (`zaynullinmi/ConverterReport`) и, если вышла новая
версия, предлагает обновиться: скачивает архив, подменяет `ConverterReport.exe` и перезапускается — настройки
сохраняются. Проверить вручную: **Справка → Проверить обновления**. Отключить проверку при запуске:
вкладка «Настройки» → «7. Обновление программы».

Нужен доступ к `github.com` (и `*.githubusercontent.com`, откуда скачивается архив); прокси Windows
используется автоматически. Если в папку программы нельзя писать или доступа нет, программа предложит открыть
страницу релиза, чтобы скачать новую версию вручную.

## Запуск по расписанию (без окна)

С параметром `--auto` программа формирует отчет без окна и сразу завершается — для Планировщика заданий Windows:

```
ConverterReport.exe --auto -t 08:00
ConverterReport.exe --auto -t 18:00
```

Ход работы и ошибки пишутся в `Отчеты\ConverterReport.log`. Задания, созданные для прежней консольной версии
(`-t 08:00 --no-pause`), продолжают работать без изменений: `--no-pause` действует как `--auto`. Все параметры:

```
      --auto              сформировать отчет без окна и выйти
  -c, --config <файл>     файл настроек (по умолчанию ConverterReport.json рядом с программой)
  -d, --date <дд.мм.гггг> дата отчета (по умолчанию — сегодня)
  -t, --time <чч:мм>      время отчета (по умолчанию ближайшее из стандартных: в 07:50 → 08:00, в 17:40 → 18:00)
      --from "<дд.мм.гггг чч:мм>"  начало отчетного периода (по умолчанию 18:00 предыдущего дня)
  -o, --out <папка>       папка для книги и PDF
      --engine <excel|builtin>  чем сохранять PDF (по умолчанию — Excel, если установлен)
  -n, --note "<текст>"    добавить строку в «Справочно» (можно несколько раз)
  -h, --help              справка
```

Без `--auto` параметры `-c`, `-d`, `-t` и `--from` открывают окно с этим файлом настроек, датой и временем отчета.

Консольная версия `ConverterReportCli` (проект `src/ConverterReport.Cli`) принимает те же параметры, а также
`--init` (создать пример настроек), `--open` и `--no-pause`.

## Сборка

Нужен .NET 8 SDK:

```
publish.cmd
```

или

```
dotnet publish src/ConverterReport.Gui -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o publish
```

Получится `publish\ConverterReport.exe`, которому не нужен установленный .NET. Номер версии (`-p:Version=2.0.N`)
подставляет сборка в GitHub Actions — по нему работает автообновление.

## Файл настроек `ConverterReport.json`

Минимально нужно перечислить этапы — их может быть сколько угодно:

```json
{
  "Projects": [
    { "Number": "2", "ScreenFile": "\\\\server\\share\\2 этап\\Экран ГГЭ 2 этап.xlsx" },
    { "Number": "3", "ScreenFile": "\\\\server\\share\\3 этап\\Экран ГГЭ 3 этап.xlsx",
      "Deadlines": {
        "Входной контроль": [ "11.06.2026", "24.06.2026" ],
        "Экспертиза":       [ "25.06.2026", "24.08.2026" ],
        "Продление 1":      [ "25.08.2026", "21.09.2026" ],
        "Продление 2":      [ "24.09.2026", "18.11.2026" ]
      }
    },
    { "Number": "9", "ScreenFile": "Экраны\\Экран ГГЭ 9 этап.xlsx", "Enabled": false }
  ]
}
```

Остальные настройки необязательны (значения по умолчанию — в `ConverterReport.sample.json`).

### Этапы (`Projects`)

| Параметр | Назначение |
| --- | --- |
| `Number` | номер этапа, как он выводится в столбце «Этап» и в именах листов Д.N/З.N |
| `ScreenFile` | путь к файлу «Экран» (абсолютный, сетевой или относительно файла настроек). Файл читается, даже если он открыт в Excel |
| `Enabled` | `false` — временно исключить этап, не удаляя его из настроек |
| `ShowInReport` | `false` — этап учитывается только на сводной диаграмме (и в листе «Свод»): в листах отчета, итогах, подписи «по … этапам» и отдельной страницей диаграмм его нет. Имена файлов и заголовок сводной диаграммы — по всем загруженным этапам |
| `LoadsAxisMax` | свой верх шкалы диаграммы загрузок этапа (по умолчанию — общий `LoadsAxisMaxProject`) |
| `Name` | имя для заголовков диаграмм (по умолчанию «N этап») |
| `Deadlines` | сроки для раздела «4. Сроки»: стадия → `[начало, окончание]` или `["произвольный текст"]`; текущая стадия подсвечивается |
| `ExpertiseEndDate` | дата окончания экспертизы (по умолчанию — наибольшая дата из `Deadlines`): ось диаграмм, «Осталось дней» |
| `ChartStartDate` | с какой даты строить диаграммы (по умолчанию — с первой заполненной строки экрана после начала сроков) |

### Отчет (`Report`)

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `ReportTimes` | `["08:00","18:00"]` | стандартные времена отчета |
| `PeriodStartTime`, `PeriodStartDayOffset` | `"18:00"`, `-1` | начало отчетного периода — 18:00 предыдущего дня |
| `OutputFolder` | `"Отчеты"` | папка для книги и PDF |
| `Version` | `"1.0"` | версия формы — подставляется в имена файлов |
| `FileName`, `DetailedFileName`, `ChartsFileName`, `WorkbookFileName` | см. sample | имена файлов. Подстановки: `{date:yyyy.MM.dd}`, `{time:H.mm}`, `{projects}` («2-4, 9»), `{projectsShort}` («2-4,9»), `{version}` |
| `PdfEngine` | `"Auto"` | `Auto` — Excel, если установлен, иначе встроенный; `Excel`; `Builtin` |
| `WorkbookMode` | `"Separate"` | `Separate` — новая сводная книга на каждый отчет; `Append` — лист дня дописывается в общую книгу |
| `MasterWorkbook` | `"Сводный отчет ГГЭ ВСМ-1"` | общая книга (режим `Append`): путь относительно папки отчетов или полный; подстановки — как в именах файлов (например, `{date:yyyy.MM}` — отдельная книга на месяц) |
| `VisibleDailySheets` | `2` | сколько последних листов дней видно в общей книге (0 — все) |
| `ImportLegacyDays`, `LegacyWorkbook` | `false`, — | переносить листы прошлых дней из старой книги (путь — относительно файла настроек или полный) и брать из нее незаполненные сроки этапов |
| `IncludeDaily`, `IncludeDetailed`, `IncludeCharts` | `true` | какие PDF сохранять |
| `IncludeDeadlines` | `true` | раздел «4. Сроки» |
| `ReportLoads` | `"Auto"` | какие загрузки выводить в разделе 1: `Auto` — в вечернем отчете (время отчета не раньше начала периода, 18:00) все загрузки за день, в утреннем — с начала периода (с 18:00 прошлого дня); `Day` — всегда за день (с 00:00); `Period` — всегда с начала периода. На диаграммах загрузки всегда за день |
| `HideProjectsWithoutLoads` | `true` | скрывать в разделе 1 этапы без загрузок |
| `LoadsMode` | `"Sum"` | для встроенного генератора: `Each` — каждая загрузка отдельной строкой |
| `NotesFile` | `"Справочно.txt"` | текст под отчетом (каждая строка — абзац, строки с `//` — комментарии) |
| `ProjectsCaption`, `Title`, `Subtitle`, `DetailedTitle` | | заголовки; в `ProjectsCaption` можно написать текст целиком без `{projects}` |

### Раскладка экрана (`ScreenLayout`)

Значения по умолчанию соответствуют текущему шаблону «Экрана»:

* **«Замечания»**, данные с 3-й строки: B — дата, D — время, E–H — всего / устранено / устраняется / рассматривается,
  I–L — инженерные изыскания, M–P — тех. часть, Q–T — сметная часть, U–X — критические, Y–AJ — критические по разделам.
  Строка учитывается, если заполнен столбец E;
* **«Документы»**, данные с 3-й строки: H/I — начало загрузки (дата/время), J/K — окончание, L–Q — ИИ, ПД, СМ, ВОР,
  КАЦ, иные (столбец «Всего» — их сумма), S — ответы, T — аннулировано, U — ошибки.
  Дата и время могут быть датой Excel, датой со временем или текстом («10.10.2026», «18:56»).

Если шаблон экрана изменится, достаточно поправить буквы столбцов в этом разделе.

### Обновление (`Updates`)

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `CheckOnStartup` | `true` | проверять новую версию при запуске окна |
| `Repository` | `"zaynullinmi/ConverterReport"` | репозиторий GitHub, из релизов которого берутся обновления |

## Как считается

* **Отчетный период** — с 18:00 предыдущего дня до времени отчета (как `AE3 = AE4 - 1`, `AF3 = 18:00` в книге).
* **Загрузки в разделе 1** — все загрузки, окончание которых попадает в выборку: в вечернем отчете — за день
  (с 00:00 отчетной даты по время отчета, та же сумма, что на диаграмме за этот день), в утреннем — с начала периода
  (начало периода не включается, время отчета включается); по этапу — их количество, начало первой, окончание
  последней и суммы по видам. Выборка задается настройкой `ReportLoads` (в окне: «Настройки → Загрузки в разделе 1»).
* **Состояние замечаний** — строка экрана на отчетные дату и время; **изменение** — разница со строкой на начало периода.
* **Свод / диаграммы** — по каждому дню срез на 18:00 (на отчетную дату — на время отчета): последняя заполненная
  строка экрана не позже среза (в тот же день; на отчетную дату — как в таблице отчета, даже если строка на время
  отчета еще не заполнена); «Устранено за сутки» — разница с предыдущим днем; загрузки — сумма за день по дате окончания (на отчетную
  дату — до времени отчета). Дни без данных (будущие даты) на диаграммах пустые — без подписей «#Н/Д», как в книге
  отчета.

## Структура решения

```
src/ConverterReport.Core     — библиотека
  Configuration/             — настройки (JSON)
  Screens/ScreenReader.cs    — чтение «Экрана» (только чтение; файл может быть открыт в Excel)
  Reporting/                 — расчет отчета, выбор времени отчета
  Workbook/                  — сводная книга: листы и формулы (ClosedXML), диаграммы (Open XML)
  Export/ExcelPdfExporter.cs — сохранение листов в PDF через Excel
  Pdf/                       — встроенный генератор PDF (MigraDoc/PDFsharp), удаление пустых страниц
  Updates/Updater.cs         — автообновление из релизов GitHub
  CommandLine.cs             — параметры запуска, журнал
src/ConverterReport.Gui      — оконная программа ConverterReport.exe (Windows Forms)
src/ConverterReport.Cli      — консольная программа ConverterReportCli
tests/ConverterReport.Tests  — тесты (xUnit) на синтетических данных
```

Библиотеки — с открытыми лицензиями (MIT): ClosedXML, DocumentFormat.OpenXml, PDFsharp/MigraDoc.

Сборка и тесты:
```
dotnet build
dotnet test
```

## Отличия от версии 1.2.2

Версия 1.2.2 («Конвертер экранов») заполняла в общей книге только блоки «Конвертер» листа дня — значениями
из **последней** строки листов «Документы» и «Замечания» пяти экранов (этапы 1–5 по номеру слота) — и пересоздавала
лист «Отчет». Остальное (Д.N/З.N, «Свод», диаграммы, время отчета, строки раздела 1, PDF) делалось вручную.

| | 1.2.2 | 2.x |
| --- | --- | --- |
| Этапы | 5 слотов | любое количество, любые номера |
| Загрузки в разделе 1 | последняя загрузка (даже если она раньше начала периода) | сумма всех загрузок: вечером — за день, утром — с начала периода |
| Строка «Замечаний» | последняя заполненная, без учета времени | строка на отчетные дату и время |
| Изменение за период | разница с листом за вчера | разница со строкой экрана на начало периода |
| Время отчета | вручную (AF4); в «Отчете» — время запуска | выбирается в окне или по расписанию, одно во всей книге и PDF |
| Экран открыт у коллеги | не читается, остаются вчерашние числа | читается последняя сохраненная версия |
| Расчеты в книге | вставленные значения | формулы со ссылками на Д.N/З.N |
| PDF | вручную | три PDF автоматически |
